# Comparison evidence

See [the comparison](../../docs/vs-ebpf.md) for interpretation and caveats.
No raw OTLP blobs or binaries are checked in.

## Original OrbStack run

`run-{97,100}hz-*` contains process rusage logs, Docker stats, decoded profile
summaries and BPF counters from the simultaneous 15-minute runs. `probes.jsonl`
contains the original shorter rate probes. The summaries' `value` is sample
count for Go CPU and nanoseconds after period conversion for eBPF CPU.
The legacy `distinct_stacks` field counts exported stack records, **not**
globally deduplicated stacks; `frames_per_stack` is unweighted by sample count.
`pct_linked_to_span` also counts context labels on the eBPF side, not only
OTLP links; the new Ubuntu reports distinguish actual links.
`run-*-s-none.json` also contains the hub's Go service profile; use only its
`ebpf:samples` entry when comparing the plain executable. The original Go
process is `demo`, the plain executable is `demo-none`.

`local-followup/` preserves all three later no-eBPF / 97-Hz / 20-Hz overhead
rounds, plus the randomized-gap 20/100/97-Hz probes. Each ran 120 seconds.
The local overhead results are noisy and are not discarded in favor of the
cleaner Ubuntu controls. `reports.jsonl` was recomputed from the retained raw
files using the current `probe-report.py`; `rusage.jsonl` and `bpf-stats.jsonl`
preserve the source measurements.

Both architecture jobs succeeded in both runs. Run 1 overall failed because
its first Kubernetes attempt could not pull/copy correctly. Run 2 succeeded
on both architectures and Kubernetes. The workflow uploaded raw profiles and
traces as compressed Actions artifacts with a **30-day retention**; compact
evidence here remains after those artifacts expire.

Each directory contains:

* `environment.txt`: original uname, CPU count, distro, BTF and Go version.
* `rusage.jsonl`: original demo exit stats, with probe name; includes duration,
  process CPU, peak RSS and allocation counts.
* `bpf-stats.jsonl`: original `native_tracer_entry` counter deltas by probe.
* `reports.jsonl`: **recomputed from raw OTLP** with the current analyzer:
  CPU/rusage, planted caller retention, inline names, hotspot shares,
  trace/span-pair matches and off-CPU durations.
* `summary.md`: regenerated readable summary of those audited reports.

Quality ran 300 s, off-CPU and each rate/overhead probe 120 s, OBI 180 s.
Off-CPU used `threshold: 0.1` (10% capture probability); reported duration sums
are sampled observations, not extrapolated totals of all native-thread waits.
The control rounds use the same plain binary with no eBPF / eBPF 97 / eBPF 20,
in that order, repeated three times; they are not randomized or blinded.

### Analysis corrections during recovery

The initial analyzer took only the first value of an aggregated off-CPU
sample. Current reports sum every nanosecond value. Thus the earlier Actions
summaries' off-CPU **percentages are superseded** here, though event counts
are unchanged. Span matches now require the **trace ID and span ID together**,
not only a span ID. CPU conversion uses the exported period, not a hardcoded
100-Hz assumption. Tests cover these cases and compressed-file input:

```sh
python3 -m unittest discover -s scripts/vs-ebpf
python3 scripts/vs-ebpf/probe-report.py /path/to/extracted/quality qotel qnone
python3 scripts/vs-ebpf/probe-report.py /path/to/extracted/obi obinone
```

## Kubernetes

`kubernetes/{default,auto}/` comes from run 2's x86-64 kind job (kind v0.33.0,
node image `kindest/node:v1.37.0`). It preserves rusage, pod listings,
profiler startup/current/previous logs and recomputed reports. Default PID
translation failed startup; `auto` exported nonzero profiles. The tested
config is generated by `scripts/vs-ebpf/k8s.sh`; it uses a privileged hostPID
DaemonSet in a disposable kind cluster, not a production cluster.
